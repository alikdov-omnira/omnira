# OMNIRO Stage 2A — Visual Design Review

Status: design prototype only. No live tenant data, API integration, workflow engine, approval behavior, or production runtime change.

## Visual hierarchy

The project is the operational nucleus inside a persistent OMNIRO presence. The spatial authority chain dominates; project context and human attention form restrained edge rails. Rectangular surfaces are reserved for readable operational evidence, not used as the primary composition.

## Interaction hierarchy

At rest, the system shows project identity, lifecycle, authoritative context, topology, and critical attention. Selecting a flow emphasizes one source-to-destination relationship. Selecting a module moves it toward focus and opens a subsystem workspace while topology, project context, and Orchestrator remain visible. Approval and explanation reveal deeper evidence only when requested.

## Module topology rationale

Nodes follow the engineering authority chain rather than arbitrary orbital placement. REAL modules are solid and available. PARTIAL modules retain operational presence with qualified state. UNAVAILABLE connections are quieter and dashed. Documents and Tasks remain contextual layers instead of authority planets.

## Approval UX rationale

Human approval is represented simultaneously as a stopped payload, a blocked downstream node, an authority marker in the topology, and the highest-priority right-rail request. The request exposes source, version, readiness, consequence, permission, and next availability. Prototype controls do not perform actions.

## Orchestrator UX rationale

The Orchestrator is a persistent system band rather than a chatbot bubble. Its expanded trace maps question, current node, source, reason, blocking dependency, human action, and next action back to the visible topology. Every statement is classified as authoritative, derived, partial, or unavailable.

## Desktop responsive rules

- 1440 px reference: 278 px project rail, flexible spatial center, 360 px attention rail, 108 px Orchestrator band.
- Below 1180 px: attention rail becomes an on-demand layer; the spatial center retains priority.
- Operational drawers never fully replace the spatial system.
- Only one selected flow receives strong payload emphasis.

## Mobile rules

Mobile is task-first: project identity, compact Core, “What needs me now?”, approval, selected flow, semantic module chain, then Orchestrator. It does not render the full desktop topology. Approval and explanation use full-screen sheets. Only one flow is visible at a time.

## Truthfulness language

- REAL: solid green-edged authority indicator; repository source available.
- DERIVED: cool blue indicator; deterministic composition from current records, not a runtime event.
- PARTIAL: amber indicator; source exists but the complete capability or integration is absent.
- UNAVAILABLE: low-emphasis dashed indicator; not connected or not implemented.

These are operational labels, never hidden debug metadata.

## Stage 1 → Stage 2 transition

The Stage 1 Core remains in-frame while the public demonstration labels dissolve. The camera moves inward across the authentication boundary. Project identity resolves as a ring around the same Core, modules reorganize into the engineering chain, and operational rails emerge from the scene edges. There is no black reset or unrelated dashboard reveal.

## Accessibility

The functional implementation must expose a semantic ordered module chain parallel to the spatial scene, visible focus states, keyboard navigation, 44 px touch targets, text equivalents for color and motion, reduced-motion transitions, live-region announcements for selection changes, and explicit confirmation dialogs for authority actions.

## Performance

The prototype assumes adaptive rendering inherited conceptually from Stage 1. Functional Stage 2A should lazy-load operational drawers, render only one active payload, cap visible topology details, pause spatial motion while hidden, preserve static/semantic fallback, and default mobile to balanced or reduced rendering. No real-time polling is implied by this visual design.
